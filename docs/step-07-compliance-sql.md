## 一、本步交付了什么

### 1. 合规三层拦截

| 层 | 实现 | 关键文件 | 为什么这样做 |
| --- | --- | --- | --- |
| 第一层 词库 | 前缀树（Trie）多模式匹配，支持中/英/西/阿变体、长词优先、英文词边界 | `app/services/compliance.py` | 确定性、可审计、单次扫描 O(文本长度×最长词长) |
| 第二层 规则 | 国别 × 物项 × 意图组合，按 priority 命中即停 | `app/services/compliance.py` | 组合判定比单词命中准确，避免"伊朗"一句话就拒答 |
| 第三层 LLM 语义 | 输出前对**回答**做规避建议判定（正则 + LLM 双检） | `check_output()` | 防"换个 HS 编码会怎样"这类改写；模型不可用时安全跳过 |

认定结果只有三种：`pass`（零感知）/ `annotate`（正常答 + 强制提示）/ `block`（拒绝 + 提示 + 留痕）。

**提示附着力（FR-304）**：提示块由服务端在流式输出结束后拼接，系统提示里也要求模型不要输出"合规免责声明"；即使模型漏了，`check_output` 也会补上。用户说"不要提示"无效——没有任何开关能关掉它。

**误拦截控制（FR-310 ≤2%）**：加了"合规知识咨询"识别。同样是"低报货值"：
- "低报货值有什么合规风险" → 提示级（在学知识）
- "低报货值具体怎么做才不被发现" → 硬拒绝（在要方法）
判定条件：出现风险/许可/认证/规定等词，且没有"规避/绕开/逃税/不被发现"等强规避动词、也没有"怎么操作/帮我"等操作诉求。

### 2. 合规词库与规则的可运营能力

- `compliance_term` / `compliance_rule`：词条与规则都进库，**不写死在代码里**（FR-301/302 热更新、可灰度、可回滚）。
- 双人复核（FR-604/FR-309）：新增词条默认 `draft`，提交人不能自己批（403），另一位合规管理员批准后 `active` 并立即失效缓存（生效 ≤5 分钟，实际是秒级）。
- 内置演示词库 22 条、规则 4 条（受制裁国别 7、管制物项 8、受限名单 3、规避话术 4）。

### 3. SQL 五铁律

| 铁律 | 代码落点 | 验证方式 |
| --- | --- | --- |
| 1 只读且权限受限 | `mode=ro` 打开 + `PRAGMA query_only` + SQLite 授权回调只放行 4 视图 | 写语句在 AST 层即拒；DB 层再兜底 |
| 2 限流访问 | `TokenBucket` 用户 10/分、会话 20/分、IP 30/分、全局 50 QPS；最大 200 行 | 超限返回 E3002 + `degraded=true` |
| 3 禁止 LLM 生成 SQL | 接口只收 `template_id + params`，无自由 SQL 入口；响应里 `llm_sql_generated=false` | `T-RAW` 直接 E3001 |
| 4 必须来自注册模板 | 代码内 4 个模板 + `sql_template` 表登记（参数 Schema/列白名单/行数/可见角色） | 模板清单固定 4 个 |
| 5 敏感表拒绝访问 | 视图不含敏感列 + AST 白名单 + 授权回调 + 列级打码 | `SELECT * FROM quotation` 被拒 |

**执行链路**：自然语言槽位抽取（确定性正则，LLM 只能输出同结构）→ 模板路由 → Pydantic 严格校验（多一个字段都拒）→ 服务端渲染（全占位符绑定）→ sqlglot AST 守卫 → 限流 → 只读执行（3s 超时）→ 列级脱敏 → `sql_exec_audit` 落库。

**行业特有校验**：汇率必带 `rate_date` + `source` + "仅供参考"；关税必带"以目的国海关最新公布为准"；**汇率超过 7 天拒绝硬算**（实测返回 E3003）。

**报价行级过滤**：`biz_group` 来自登录用户，前端传了也会被 Pydantic 拒绝（`extra=forbid`）——想查别组报价没有入口。

### 4. 与问答链路的集成

```
提问 → 合规预检（词库+规则）
        ├─ block → 直接拒答（不检索、不给引用）
        └─ 继续 → SQL 通道（命中模板则结构化作答）
                    └─ 未命中/空/限流 → 降级文档检索（meta.sql_degraded=true）
                 → 检索 → LLM 流式生成
                 → 输出前兜底（正则+LLM）→ 提示附着 → 落库（compliance_flag）
```

- `message.compliance_flag` 记录 `block` / `annotate`，会话历史可直接看出哪条被拦截。
- 提示级问题采用"先收齐再吐字"（buffered），避免"先输出违规内容再撤回"。
- 普通问题保持流式；若输出侧仍判定违规，追加 `override` 事件，前端用它替换已显示文本（已写入文档的已知折衷）。

## 二、自查发现并修复的问题（6 个）

1. **语法错误**：`guard_sql` 里 `return False f"..."` 漏逗号 → 编译期发现并修复。
2. **只读连接误杀视图**：SQLite 展开视图时会读基表，授权回调只放行视图名导致 `access to fx_rate... is prohibited`。修复：放行"视图 + 其基表 + sqlite_master"，直接查基表由 AST 守卫拦截（分层防御，已写注释）。
3. **危险函数漏检**：sqlglot 把未知函数解析成 `Anonymous`，`sql_name()` 不是真实函数名，`load_extension()` 未被拦。修复：同时读取 `Anonymous.name` + 对 SQL 文本做函数名正则兜底。
4. **缓存 ORM 对象导致 500**：规则缓存存了 `ComplianceRule` 实体，Session 关闭后读属性抛 `DetachedInstanceError`。修复：缓存不可变值对象 `RuleEntry`。
5. **误拦截**："向伊朗出口无人机需要什么许可" 被高危规则判成 block。修复：知识咨询识别覆盖"许可/认证/申请/审批"等词，同时用强规避动词做否定保护。
6. **PRD 原句没命中**："把货报成低价值样品质" 不含"低报"，原正则漏掉。修复：补充"报成低价值/按样品申报/少交关税"等变体，并新增 `evade_duty` 意图。

## 四、错误码约定（E3xxx / E5xxx）

| 码 | 场景 | 用户可见文案 |
| --- | --- | --- |
| E3001 | 模板未匹配 / 未注册 | 该数据查询暂不支持，已转为文档检索 |
| E3002 | 触发限流 | 该数据查询暂不支持（已触发访问频率限制），已转为文档检索 |
| E3003 | 汇率源不可用 / 过期 >7 天 | 最近汇率已超有效期，按规则不做换算 |
| E3004 | 参数校验失败 | 查询参数不合法 |
| E3005 | AST 守卫拒绝 | 该数据查询暂不支持，已转为文档检索 |
| E5001（合规 block） | 命中红线 | 该问题涉及贸易合规限制，已记录并转合规复核 |
